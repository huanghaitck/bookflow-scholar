如何获取 API Key
并配置文本与视觉模型

以 DeepSeek 文本模型和 GLM 视觉模型为例。适用于 Bookflow Scholar 0.8.0-rc.2。

先说清楚：API Key 通常不需要“购买”。

你在官方开放平台免费创建密钥；真正产生费用的是模型调用。先查看赠送额度，再按需要小额充值。价格、模型名和活动会变化，请以官方平台当天页面为准。

1进入官方开放平台并注册
2完成认证，查看赠送额度或充值
3创建 API Key，并只复制一次
4在 Bookflow 填写 Base URL、Key、Model
5保存并测试连接，确认 T/V 已就绪

推荐的入门组合

文本翻译：DeepSeek

作为入门推荐已经足够，适合正文翻译与结构化文本任务。模型名更新较快，应从官方“首次调用 API”页面复制当前名称。

视觉版面：GLM 视觉资源包

优先购买与视觉模型对应的资源包，用于复杂论文、扫描页、地图、图版、表格与疑难页。示例：glm-4.6v。

重要：只在官方域名注册、充值和创建密钥。不要购买第三方转售 Key，不要把 Key 发给维护者，也不要把它粘贴进 Issue、截图或日志。
核验日期：2026-07-24 · 官方页面如有调整，以平台最新界面为准
B GLM｜智谱开放平台

GLM：注册、充值与创建 API Key

官方平台：https://open.bigmodel.cn/

步骤

  1. 打开智谱开放平台，选择“注册/登录”，按平台要求完成账号与实名认证。
  2. 先查看新用户赠送额度。需要付费时，推荐进入“特惠专区/资源包”，选择当前在售的视觉推理模型资源包；资源包模型必须与 Bookflow 中填写的 Model 一致。
  3. 进入“个人中心 → API Keys”，创建标准开放平台 API Key：
    https://open.bigmodel.cn/usercenter/proj-mgmt/apikeys
  4. 立即复制并妥善保存。平台可能不会再次完整显示同一个 Key。
Bookflow 字段GLM 示例
角色视觉模型服务；GLM 也可用于文本角色
Base URLhttps://open.bigmodel.cn/api/paas/v4/
API Key粘贴刚创建的标准开放平台 Key
Model资源包示例：glm-4.6v；若购买 FlashX 或其他视觉包，填写对应的官方模型名
买视觉资源包，不要买 Coding Plan：GLM Coding Plan 可能使用专属 Key 和专属端点，不是本指南推荐的 Bookflow 视觉额度。请选择适用于标准 API 的视觉模型资源包，并使用标准开放平台 Key 与通用 Base URL。资源包通常有模型范围和有效期，付款前请逐项核对。

官方参考

  • 智谱快速开始
  • 模型概览与当前模型名
  • 特惠专区与视觉模型资源包
  • HTTP API、Base URL 与鉴权
成本建议

DeepSeek 负责文本翻译已经足够；GLM 只承担视觉版面任务。先用两页公开测试 PDF 完成连接和小规模处理，再导入长书，避免把视觉额度消耗在不需要多模态判断的页面上。

B DEEPSEEK｜开放平台

DeepSeek：注册、充值与创建 API Key

官方平台：https://platform.deepseek.com/

步骤

  1. 打开 DeepSeek 开放平台，注册并登录。需要在线充值时，按平台要求完成实名认证。
  2. 在“充值”页面查看余额并按需小额充值。官方 FAQ 说明，个人在线充值可使用支付宝/微信，当前充值余额永久有效；活动赠送余额可能另有期限。
  3. 进入“API Keys”，创建一个新 Key：
    https://platform.deepseek.com/api_keys
  4. 复制并安全保存。建议为不同应用创建不同 Key，便于撤销和排查用量。
Bookflow 字段DeepSeek 示例
角色文本模型服务
Base URLhttps://api.deepseek.com
API Key粘贴刚创建的 DeepSeek Key
Model从官方“首次调用 API”页面复制当前模型名
模型名会更新：截至本指南核验日，官方页面列出 deepseek-v4-flash 与 deepseek-v4-pro，并提示旧模型别名正在弃用。不要长期照抄旧教程中的模型名。

官方参考

  • 首次调用 API、当前模型名与 Base URL
  • 模型与价格
  • 充值、余额与常见问题
为什么仍要配置视觉 Provider？

DeepSeek 示例承担文本翻译。论文复杂版面、扫描图、地图、照片、表格和疑难页还需要一个能接收图像的视觉模型，例如 GLM 的视觉模型。

B BOOKFLOW SCHOLAR｜桌面端配置

在 Bookflow Scholar 中配置

  1. 启动桌面客户端，创建或打开项目。
  2. 打开左侧“模型服务”。页面中有“文本模型服务”和“视觉模型服务”两个独立角色。
  3. 分别填写 Base URL、API Key、Model，点击“保存”。
  4. 点击“测试连接”。顶部应显示 T · 已就绪、V · 已就绪。
  5. 先导入两页公开 PDF 做小规模测试；连接与输出正常后再处理长书。
Key 只在桌面客户端输入，默认隐藏。
Key 保存到 Windows 凭据管理器，不写入项目文件。
Base URL 不要粘贴聊天接口的完整路径。
模型名必须与该平台当前开放的名称完全一致。

连接失败时按顺序检查

现象优先检查
401 / 鉴权失败Key 是否复制完整、是否属于当前平台、是否误用套餐专属 Key
404 / 模型不存在模型名是否过期，Base URL 是否正确
429 / 额度或频率问题余额、并发限制、调用频率；稍后重试或充值
视觉处理失败视觉角色是否配置了真正支持图片输入的模型
网络错误本机网络、代理、防火墙，以及官方平台服务状态
安全底线：不要通过邮件、Issue、聊天截图或日志发送 API Key。怀疑泄露时，立即在 Provider 平台撤销旧 Key，创建新 Key，并检查账单与用量。
